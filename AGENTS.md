# Aturan Kerja Web Porto Wingman Clutch

Repo ini dikerjakan berdua oleh **Kall** ([@HaikalFaruq](https://github.com/HaikalFaruq)) di frontend dan **Bintang** ([@bintangfabian](https://github.com/bintangfabian)) di backend, sering dengan bantuan AI agent. Aturan di bawah berlaku untuk kita berdua dan untuk agent apa pun yang dipakai.

Sumber kebenaran produk ada di [PRD](docs/prd/PRD-WingmanClutch.md). AI agent wajib membaca file ini sampai habis sebelum mengubah apa pun, lalu membaca panduan sesuai peran orang yang menjalankannya (bagian 5).

## 1. Tanpa atribusi AI

Commit, PR, issue, dan komentar tercatat atas nama orang yang menjalankannya. Jangan tulis atribusi AI dalam bentuk apa pun:

- Trailer seperti `Co-Authored-By: Claude <noreply@anthropic.com>`, `Claude-Session: …`, `Assisted-by: …`, dan trailer sejenis dari agent lain (Codex, Copilot, Cursor, Gemini, Aider, Devin, Jules, Amp, Warp, dan seterusnya).
- Footer seperti `🤖 Generated with Claude Code` atau `Generated by Copilot`, serta link sesi agent.
- Agent atau bot AI sebagai author atau committer, misalnya `claude[bot]`, `Copilot`, `Cursor Agent`, `devin-ai-integration[bot]`, atau nama berakhiran `(aider)`. Commit selalu memakai identitas git kamu sendiri.

Kalau agent kamu menambahkan atribusi otomatis, matikan di setting-nya. Untuk Claude Code sudah dimatikan lewat `.claude/settings.json` di repo ini.

Aturan ini dicek berlapis, jadi pelanggaran berhenti sebelum masuk `main`:

| Lapis | Yang dicek | Kapan |
| --- | --- | --- |
| `.githooks/commit-msg` | Pesan commit | Setiap `git commit` |
| `.githooks/pre-push` | Author, committer, dan pesan semua commit yang di-push | Setiap `git push` |
| Workflow `No AI attribution` | Sama seperti pre-push, plus judul dan deskripsi PR | Setiap PR dan push ke `main` |
| Branch protection `main` | Hanya menerima commit yang lolos cek `no-ai-attribution`, termasuk dari admin. Force push dan hapus `main` diblokir | Di GitHub |

Hook aktif otomatis setelah `pnpm install` (script `prepare`). Tanpa pnpm, aktifkan sekali per clone:

```sh
git config core.hooksPath .githooks
```

Kalau ditolak, perbaiki commit-nya. Jangan lewati hook dengan `--no-verify`, karena CI tetap menolaknya.

| Kasus | Perintah |
| --- | --- |
| Pesan commit terakhir | `git commit --amend`, lalu hapus atribusinya |
| Author commit terakhir | `git commit --amend --reset-author --no-edit` |
| Commit yang lebih lama | `git rebase -i origin/main`, tandai `reword` atau `edit`, lalu `git push --force-with-lease` ke branch fitur kamu, tidak pernah ke `main` |

Semua pola ada di `scripts/check-no-ai.sh` dan contohnya di `scripts/test-check-no-ai.sh`. Kalau ada agent baru yang lolos, tambahkan pola dan contohnya lewat PR.

## 2. Pasangan jadi co-author

Setiap commit menyertakan pasangan sebagai co-author, supaya begitu PR-nya di-merge kita berdua dapat achievement **Pair Extraordinaire**. Ini trailer manusia, jadi tidak ikut ditolak cek di bagian 1.

| Yang commit | Trailer di akhir pesan commit |
| --- | --- |
| Kall | `Co-authored-by: Bintang Fabian Putra <47806878+bintangfabian@users.noreply.github.com>` |
| Bintang | `Co-authored-by: Muhammad Haikal Faruq <50310521+HaikalFaruq@users.noreply.github.com>` |

- Taruh trailer di baris paling akhir, dipisah satu baris kosong dari isi pesan.
- Pakai email noreply di atas supaya co-author pasti terhubung ke akun GitHub masing-masing.
- Merge PR pakai **Create a merge commit** (`gh pr merge --merge`). Squash dan rebase dimatikan di repo ini, karena PR yang di-squash tidak memberi badge.

## 3. Pesan commit dan PR harus bisa dilanjutkan

Siapa pun yang baca harus langsung paham apa yang berubah dan bisa lanjut dari situ.

**Commit:** format Conventional Commits dalam Bahasa Indonesia (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `test:`). Judul maksimal 72 karakter. Isi pesan menjelaskan apa yang berubah dan kenapa.

**PR:** deskripsi mengikuti template `.github/pull_request_template.md`.

```markdown
## Apa yang berubah
## Kenapa
## Sudah dicek
## Selanjutnya
```

Bagian **Selanjutnya** berisi langkah berikutnya, hal yang belum beres, atau keputusan yang perlu diambil pasangan. Jangan dikosongkan.

## 4. Alur kerja

Branch (`feat/…`, `fix/…`, `docs/…`) → PR → review pasangan → merge, satu PR untuk satu topik. Jangan push langsung ke `main` (branch protection juga menolaknya).

Setiap mulai sesi, termasuk sesi AI agent:

1. Sinkron dulu: `git switch main && git pull`.
2. Pastikan hook aktif: `git config core.hooksPath` harus mengeluarkan `.githooks`.
3. Buka checklist peranmu (bagian 5), ambil item pertama yang belum dicentang, lalu kerjakan lewat alur di atas.
4. Centang item itu di PR yang sama.

## 5. Peran dan area kode

| Area | Pemilik | Isi |
| --- | --- | --- |
| `apps/web/` | Kall | Halaman buku catatan: mesin pensil, sketsa, figur, tata letak, pensil dan penghapus, tema, dialog, mock API |
| `api/` | Bintang | Vercel Functions `kontak` dan `proyek`, beserta test-nya |

| `vercel.json` | Berdua | Build, header keamanan, dan rute Functions |
| `docs/` | Berdua | PRD, panduan peran, desain, aset, diagram arsitektur |

- **Agent untuk Bintang** bekerja sebagai backend engineer. Mulai dari [docs/backend.md](docs/backend.md): cakupan, keputusan yang menunggu, checklist, rancangan endpoint, dan syarat keamanan.
- **Agent untuk Kall** bekerja sebagai frontend engineer. Mulai dari [docs/frontend.md](docs/frontend.md): cara menjalankan, cara kerja mesin pensil, cara menambah sketsa, dan checklist.
- Kontrak dulu, kode kemudian. Endpoint baru atau perubahan bentuk data masuk ke `docs/api/openapi.yaml` lewat PR yang di-review pasangan, baru diimplementasikan. Frontend jalan dengan mock dari kontrak itu (`apps/web/mock/api.ts`), dan unit test memvalidasi mock dengan skema kontrak, jadi kontrak dan mock selalu berubah di PR yang sama.
- Jangan mengubah area pasangan tanpa bilang dulu. Kalau butuh perubahan di sana, tulis di bagian **Selanjutnya** PR kamu.
- Secret (API key Resend, token GitHub) tidak pernah di-commit. Pakai `.env` dan sediakan `.env.example`.

## 6. Perintah

Butuh Node 24 (`.nvmrc`) dan pnpm 9. Semua perintah dijalankan dari root repo.

| Perintah | Fungsi |
| --- | --- |
| `pnpm install` | Pasang dependensi dan aktifkan hook git |
| `pnpm dev` | Server development halaman di http://localhost:5180, dengan mock API |
| `pnpm build` | Build produksi ke `apps/web/dist` |
| `pnpm lint` | oxlint (warning dianggap gagal) dan Prettier |
| `pnpm typecheck` | Cek tipe semua package |
| `pnpm test` | Unit test Vitest semua package |
| `pnpm test:e2e` | E2E Playwright di build produksi (desktop, Android, iPhone) |
| `pnpm check` | `lint`, `typecheck`, dan `test` sekaligus |
| `pnpm --filter @wingmanclutch/web font` | Buat ulang data font pensil (`src/data/font.json`) |
| `node apps/web/scripts/buat-logo.mjs` | Buat ulang data logo (tulisan WINGMAN CLUTCH di halaman, lambang di kartu nama) dari `docs/brand/wingman-clutch-logo.svg` |
| `pnpm --filter @wingmanclutch/web figur` | Buat ulang halaman figur dan gambar diamnya di `apps/web/public/figur/` dari `apps/web/figur/` (butuh `python3` dan Chrome Playwright) |
| `node apps/web/scripts/buat-gambar.mjs` | Buat ulang gambar README dan gambar OG dari build produksi (butuh Chrome Playwright) |
| `scripts/check-no-ai.sh --revs origin/main..HEAD` | Cek atribusi AI di commit yang belum masuk `main` |
| `scripts/test-check-no-ai.sh` | Uji pola cek atribusi AI, wajib lolos setelah polanya diubah |
| `scripts/check-secrets.sh --staged` | Cek rahasia di perubahan yang di-stage (otomatis lewat hook `pre-commit`) |
| `scripts/test-check-secrets.sh` | Uji pola cek rahasia, wajib lolos setelah polanya diubah |

Sebelum push, pastikan `pnpm check` dan `pnpm test:e2e` lolos. Perilaku baru wajib disertai test: logika di unit test, alur pengguna di E2E. Pertama kali di mesin baru: `pnpm --filter @wingmanclutch/web exec playwright install chromium webkit`.

Perintah backend (dipakai setelah `api/` dibuat, lihat [docs/backend.md](docs/backend.md)):

| Perintah | Fungsi |
| --- | --- |
| `npx vercel@latest dev` | Halaman dan Functions sungguhan di http://localhost:3000, membaca `.env` |
| `API_PROXY=http://localhost:3000 pnpm dev` | Halaman di Vite dengan `/api` diteruskan ke `vercel dev`, bukan mock |
| `pnpm --filter @wingmanclutch/api test` | Unit test handler |
| `npx @redocly/cli@1 lint docs/api/openapi.yaml` | Validasi kontrak API |

## 8. Aturan produk

- **Buku catatan berisi figur.** Tata letak dan urutan menggambar berangkat dari [kracked.studio](https://kracked.studio) (catatan di [docs/referensi/kracked-studio.md](docs/referensi/kracked-studio.md)). Sejak 31 Oktober 2026 Kall dan Bintang sepakat semua benda di halaman digambar sebagai figur Colorfigures (empat aplikasi, tim, lambang, lampu, kopi), halaman dibuka dengan layar pembuka, dan tema diganti lewat tali lampu. Tulisan, catatan, dan coretan tetap digambar mesin pensil. Isinya milik Wingman Clutch: logo, empat aplikasi, tim, dan teks berbahasa Indonesia.
- Kode, gambar, logo, dan foto dari web referensi tidak boleh disalin ke repo. Kita menulis ulang mesin pensil dan menggambar sketsa sendiri; yang ditiru hanya cara kerja dan rasanya. Catat sumber dan lisensi setiap aset di `docs/assets.md`.
- Isi halaman (nama aplikasi, teks, tautan, tim) ada di `apps/web/src/data/proyek.ts`, bukan di dalam sketsa atau komponen.
- Warna pensil dan kertas per tema ada di `apps/web/src/engine/kuas.ts` dan `apps/web/src/halaman/kertas.ts`. Jangan menulis warna baru langsung di sketsa; pakai kode warna pensil (`w`, `k`, `e`, `y`, `p`, `b`, `g`, `o`, `r`, `n`).
- Semua figur dimodelkan di `apps/web/figur/`. Setelah mengubahnya, jalankan `pnpm --filter @wingmanclutch/web figur` dan commit hasilnya, karena build produksi tidak menjalankan Python. Engine di `figur/colorfigures/` tidak diubah langsung; penyesuaian masuk `figur/sematan.css` dan `figur/sematan.js`.
- Halaman harus muat di satu layar tanpa scroll, dari HP 320 px sampai desktop lebar. Unit test tata letak menjaga semua sketsa tetap di dalam halaman dan tidak saling tindih.
- Bukan target rilis 1: CMS, blog, multi-bahasa, analitik pihak ketiga, akun pengunjung.

## 9. Rahasia dan data pribadi

Repo ini public: commit, PR, issue, dan komentar bisa dibaca siapa saja.

- Secret key, token, password, dan isi `.env` tidak pernah masuk commit, PR, issue, maupun komentar. Kirim lewat jalur privat.
- Frontend tidak memegang secret apa pun. API key Resend dan token GitHub hanya ada di Environment Variables Vercel dan `.env` lokal backend, dengan contoh di `.env.example`.
- Key yang sempat terkirim lewat chat atau tertempel di tempat publik dianggap bocor: rotate di dashboard, tidak cukup dihapus dari commit.
- Commit memakai email noreply GitHub supaya email pribadi tidak tampil. Alamatnya sama dengan tabel co-author di bagian 2: `git config user.email <id>+<username>@users.noreply.github.com`.
- Pesan dari form kontak berisi data pribadi pengunjung. Jangan menyimpannya di repo, log Functions, atau issue. Alamat IP hanya dipakai untuk batas kirim, dalam bentuk hash.
- Screenshot web referensi tidak disimpan di repo; `docs/referensi/` hanya berisi catatan.

Penjaganya berlapis. Hook `.githooks/pre-commit` (`scripts/check-secrets.sh`) menolak file `.env` dan pola secret sebelum commit, dan workflow `Web` menjalankan cek yang sama ke semua berkas yang di-track di setiap PR. Setelah itu, secret scanning dan push protection GitHub menolak push yang memuat secret yang dikenali.
